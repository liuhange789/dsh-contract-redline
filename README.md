# dsh-contract-redline

> 签字之前，先花 30 秒看看这份合同里有没有坑。

合同风险速查插件：把采购合同、租赁合同、服务协议的正文粘进 DSH，工具逐条扫描，输出一份**风险清单**——哪些条款对你不利、哪些关键条款压根没写。

**只是条款提示，不是法律意见。** 不判断合同是否有效，不评价该不该签，不替代律师。

---

## 它解决什么问题

中小企业老板、行政、HR 每年要签几十份合同，却没有法务部门，也不可能每份都找律师（一份几百到几千块）。而 90% 的合同风险是重复的、模式化的：管辖地固定在对方城市、违约责任只写你、验收标准只有“符合甲方要求”、押金不写怎么退。

这个插件在找律师之前先帮你把这类条款挑出来，让你知道该问什么。

## 边界

| 做 | 不做 |
| --- | --- |
| 定位高风险条款并摘录原文 | 出具法律意见 |
| 标出权利义务不对等的条款 | 判断合同是否有效、是否违法 |
| 列出缺失的关键条款 | 告诉你“签”或“不签” |
| 每条附一句预写的白话解释 | 起草、修改合同 |
| 纯文本扫描（不做 OCR） | 接入外部法律数据库或联网 |

每条风险都会带上固定的免责声明：**仅为条款位置与风险提示，不构成法律意见，不判断合同是否有效，不替代律师。**

## 用法

```
contract_scan(text: "<合同全文>")
```

识别不准时可指定类型：

```
contract_scan(
  text: "...",
  contract_type: "lease"   // auto | procurement | lease | service
)
```

输出（会话里直接渲染成清单，JSON 里同时给结构化字段）：

```
【合同风险速查】
识别类型：租赁合同｜条款 8 条｜规则集 2026.11
按 2026.11 规则集扫描 8 条条款（租赁合同）：高风险 3 处、权利义务不对等 1 处、关键条款缺失 1 项。…

高风险条款（3）
  1. 押金没有约定退还条件
     条款：…月租金 6000 元，押金为三个月租金，用于担保乙方履行本合同义务。…
     为什么：只写收多少押金、不写什么条件下退、多久退，退租时容易以“房屋损耗”等理由被全部扣留。
  2. 维修责任全压给一方
  3. 自动续约 / 自动顺延

权利义务不对等（1）
  1. 只有一方可以解除 / 提前终止

关键条款缺失（1）
  - 争议解决方式（仲裁或诉讼管辖）

声明：仅为条款位置与风险提示，不构成法律意见，不判断合同是否有效，不替代律师；重要合同请交由专业人士审阅。
```

## 规则集（2026.11）

**通用高风险**

| 规则 | 触发方式 |
| --- | --- |
| 管辖地固定在单方所在地 | 「乙方所在地人民法院管辖」这类指向某一方城市的表述 |
| 自动续约 / 顺延 | 「未提出异议即自动续期」 |
| 责任表述过宽 | 「承担全部损失 / 一切责任 / 无限连带」 |
| 单方变更权 / 最终解释权 | 对方可单方调价、调条款 |

**采购 / 供货 / 服务专项**

| 规则 | 触发方式 |
| --- | --- |
| 付款时间没有明确期限 | 有“支付/结算”，但只有“另行协商 / 视情况 / 收到发票后”，没有具体天数 |
| 验收标准不可量化 | 有“验收”，但标准只有“符合甲方要求 / 甲方认可” |
| 一次性全额预付 | 「一次性全额支付 / 先付清」 |

**租赁专项**

| 规则 | 触发方式 |
| --- | --- |
| 押金没有退还条件 | 有押金，但全文没有“退还 / 返还” |
| 维修责任全压给一方 | 维修条款只出现出租方或只出现承租方 |
| 提前解约不对等 | 见下 |

**权利义务不对等**

| 规则 | 触发方式 |
| --- | --- |
| 只有一方可以解除 / 终止 | 解除权只写给一方（会区分是不是双方都有） |
| 违约责任只约束一方 | 违约金 / 赔偿条款只出现被约束的一方 |

**关键条款缺失**（按合同类型检查，全文没有对应关键词就列入缺失）

- 通用：争议解决方式、合同期限与生效条件
- 采购 / 服务：付款条件与账期、验收标准与流程、知识产权 / 成果归属
- 租赁：押金及退还条件、维修责任划分、提前解约条款

规则全部写在 `src/rules.js`，改词表或阈值后 `npm run build` 即可；版本号随规则集变化。

## 为什么不会越界成“法律意见”

- 每条提示只描述**条款文本特征**和**为什么这通常在商业上不利**，不引用法条、不下有效性结论；
- 不输出“建议签 / 不建议签 / 合同无效 / 违法”这类判断，测试里有专门的断言守着这条线；
- 类型识别不准时会明说「未识别类型（按通用规则扫描）」，不硬套专项规则；
- 文本不足 80 字符直接报错，不凭片段猜结论；
- 网络与文件系统零依赖：工具不联网、不写文件、不记录内容。

```bash
dsh plugin add @liuhange/dsh-contract-redline
```

## 开发

```bash
npm install
npm test        # 构建 + 12 个测试
npm run build
```

目录：

```
src/rules.js         规则集、条款切分、扫描与文本渲染
src/host/index.js    contract_scan 工具
test/samples.js      采购 / 租赁 / 服务三份样本 + 一份条款对等的干净样本
test/scan.test.js    预设风险点命中、无法律意见、结构完整性、不误报
```

测试覆盖：

- 三份样本的预设风险点全部命中（采购 6 处、租赁 4 处、服务 5 处）与缺失项；
- 条款对等的干净租赁合同零误报；
- 输出不含“签 / 不签 / 无效 / 违法”判断；
- 每条风险有标题、≤90 字摘录与白话解释；
- 类型自动识别与手动覆盖、条款切分、短文本报错。

## FAQ

**能扫劳动合同吗？** MVP 规则集只覆盖采购 / 供货、租赁、服务/委托三类；劳动合同会按通用规则扫描，专项规则不适用。

**能改规则吗？** 可以，`src/rules.js` 里每个规则都是「正则 + 标题 + 一句解释」，加规则不需要模型。

**会联网或上传合同吗？** 不会。纯本地规则匹配，合同文本不落盘。
